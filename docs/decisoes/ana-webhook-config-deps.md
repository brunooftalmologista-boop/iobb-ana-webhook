## Envs novas (12/08/2026) — o Dr. Bruno liga e desliga no Render, sem deploy

- **`PAINEL_JANELA_HORAS=96`** — a lista do painel passa a mostrar só os últimos N horas (886 conversas → ~100, 366 KB → 43 KB). **Sem a env, a lista vem inteira** (comportamento antigo), então desligar é apagar a variável. O valor 96 saiu do pior momento da SEMANA: segunda às 8h o último expediente foi sexta às 18h, 62h antes — abaixo de 72h a equipe chega na segunda sem ver a sexta (com 12h veria UMA conversa). Os 4 dias dão folga para feriado de segunda. O payload não cresce depois disso (72h=41 KB, 96h=43 KB, 7d=69 KB), então **apertar a janela não economiza nada** — na dúvida, errar para o lado longo. Conversa pendente (human/team_flag/não lida) fica na lista por mais velha que seja, e a busca varre tudo pelo servidor (`?q=`), então nada some de verdade.
- **`WA_ESPELHO_EXTRA=5561992997639`** — número(s) extra que recebem o mesmo espelho de `notificarClinica` (toda mensagem de paciente + resposta da Ana). ⚠️ **Não é arquivo confiável**: a Meta bloqueia envio para quem não escreve à clínica há 24h, e número que só recebe é exatamente esse caso. O Dr. Bruno assumiu mandar uma mensagem por dia de lá. Se escapar, a 3ª falha seguida dispara UM aviso no número principal explicando a causa — o contador zera ao voltar.

**⚠️ `conversations.updated_at` é `timestamp WITHOUT time zone` guardando UTC** (igual a `messages.timestamp`). Para exibir em BRT use `- interval '3 hours'`; **`at time zone 'America/Sao_Paulo'` faz o oposto** (interpreta como BRT e devolve UTC), e foi assim que eu produzi números errados por 3h numa análise em 12/08. O filtro do código está certo porque a sessão do Supabase roda em UTC.

Key config/deploy facts not obvious from code:
- Supabase schema migrations are applied MANUALLY by the user in the Supabase SQL Editor. Migration files live in `sql/*.sql` (e.g. `ad_clicks.sql`, `messages_media.sql`). New columns/tables require a matching sql file AND the user running it.
- Env vars on Render: values must be the bare value (a paste bug once put `PHONE_NUMBER_ID=...` into the value itself; `readEnv()` now sanitizes a `NAME=` prefix + quotes, and dotenv uses `override:true` so `/etc/secrets/.env` wins).
- Sending a WhatsApp message OUTSIDE Meta's 24h customer-service window requires an approved template. Configure `WA_TEMPLATE_NAME` + `WA_TEMPLATE_LANG` (default pt_BR) on Render; without them, `/api/conversations/new` returns 409 for out-of-window patients.
- Agenda/horários: the doctor's availability comes from a public Google Calendar iCal (`ICAL_URL`). Fetch it DIRECTLY server-side (`fetchICS`) — no CORS server-to-server. The old `allorigins.win` proxy went down and silently emptied availability, making Ana invent/deny slots. The iCal is a free/busy export: events are `SUMMARY:Busy` with `DTSTART:...Z` (UTC). Unit is inferred by weekday (`AGENDA_REGRAS`: Conjunto=Mon/Wed/Fri, Taguatinga=Tue/Thu) — confirm with user if the real schedule differs. When the agenda fails to load, `fetchSlots` returns `null` and the prompt forbids inventing times. Live check: `GET /api/diag/agenda` (auth).
- Supabase Storage (private bucket `anexos`) uploads REQUIRE the `service_role` key in `SUPABASE_KEY` on Render. DB table writes can succeed with the anon key if table RLS is disabled, but Storage enforces RLS independently — so an anon key = DB works but attachment uploads silently fail (`storeInboundMedia` returns null, no `media_path` saved). Diagnostics added: startup logs the key role; `GET /api/diag/storage` (auth) self-tests upload→sign→remove. Also note: media messages saved BEFORE the `messages_media.sql` migration ran have null `media_path` and can't be opened — must test with a NEW file.
- Pré-agendamento → secretária: when Ana finishes collecting a pre-booking she appends a hidden `[PREAGENDAMENTO]...[/PREAGENDAMENTO]` block (one `nome: ... | telefone: ... | convenio: ... | unidade: ... | periodo: ... | motivo: ...` line per patient). `extrairPreAgendamento()` strips it from the patient-facing text (even if the closing tag is missing) and `notificarSecretaria()` sends a formatted summary to `WA_SECRETARIA_NUMBER` (env; default `5561992997639`). Same Meta 24h-window caveat: if the free-form send fails, it logs and mirrors to `NUMERO_CLINICA` as a fallback so it's never lost. To reliably receive, that number must have messaged the Business number within 24h, else an approved template is needed.
- Recado → secretária (generalizes the mirror to any hand-off to the human team): when Ana forwards something ("vou repassar/encaminhar", pedido de humano, dúvida que não resolve, urgência/angústia) she appends a hidden `[RECADO] tipo: dúvida|urgência|pedido de contato humano | prioritario: sim/não | resumo: ... [/RECADO]` block. `extrairRecado()` strips it (missing-close-tag safe; accepts `:` or `=` and `|`/newline) and `notificarRecadoEquipe()` sends `🔔 RECADO PARA A EQUIPE` (with `⚠️ PRIORITÁRIO` on top when `tipo` contains "urgência" or `prioritario: sim`) to `WA_SECRETARIA_NUMBER`, same 24h fallback. Anti-dup: `[RECADO]` is parsed from the text already cleaned of `[PREAGENDAMENTO]`, and the webhook uses `else if` — a pre-agendamento never also fires a recado; the prompt also forbids emitting both.
